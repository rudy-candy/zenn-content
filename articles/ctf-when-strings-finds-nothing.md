:::message
2026年10月追記：picoCTF は CyLab Security Academy（learn.cylabacademy.org）に名前が変わり、フラグの形式も多くの問題で `picoCTF{...}` から `academy{...}` に変わりました（一部、今も picoCTF{ のままの問題もあります）。
:::

Forensics の問題をもらったとき、私がまず打つのは `strings` です。ディスクイメージでも、拡張子のないファイルでも、とりあえず全体を読ませてフラグの頭を `grep` する。これが一発で当たる問題はたしかにあって、そのときは1秒で終わります。

困るのはその次です。同じ手が通じない問題に当たると、「0件＝フラグが無い」と早合点して、ステガノ用の専用ツールを手当たり次第に試す遠回りをしがちです。私自身が何度もやりました。

この記事は、`strings` が空振りしたときに私が順番に見ていく場所を、実際に解いた問題と結びつけて並べたものです。1問ずつの完全な手順はnoteの各writeupに書いています。ここでは「次にどこを疑うか」という分かれ道だけを扱います。

## まず「空振り」の意味を切り分ける

0件が出たとき、私は先に2つを疑います。

1つ目は検索語です。CyLab Security Academy への移行で、フラグの頭が `picoCTF{` から `academy{` に変わった問題が多くあります。`picoCTF{` で `grep` して0件でも、`academy{` なら出ることがあります。どちらで探して0件なのかは、毎回はっきりさせておくと後が楽です。

2つ目は、そもそもフラグが平文で置かれているのか、という点です。`strings` が読むのはあくまで「そのまま並んだ文字」です。エンコードされていたり、圧縮されていたり、画像として描かれていたりすると、文字列としては出てきません。ここから先は、その「出ない理由」ごとに見る場所が変わります。

## 1. ファイルシステムの中（strings はそこを読まない）

ディスクイメージで `strings` が0件なら、フラグがファイルの中に正しく収まっていて、生のセクタには散らばっていない、という可能性があります。`strings` はファイルシステムの構造を無視して全部のバイトを読むので、逆に言うとファイルの中身を1つずつは見ていません。

DISKO 3 がこれでした。ディスク全体が1つの FAT32 で、`strings | grep` は0件。フラグは `log/flag.gz` という1ファイルの中に gzip で圧縮されて置いてありました。Sleuth Kit の `fls` でファイル一覧を出し、`icat` で取り出して展開する、という流れになります。`strings` は圧縮の中までは読みません。

- [DISKO 3 のwriteup（note）](https://note.com/rudy_candy/n/n6c31fb2e4db5)

## 2. パーティションを切り出した先

これは逆に、`strings` が出すぎて困るパターンの対処です。DISKO 2 ではディスク全体に `grep` をかけると候補が125個も出ました。おとりがパーティションの外や別のファイルシステムに撒いてあったからです。問題文の「Linux」という一言を手がかりに、`mmls` でパーティション表を読み、目的のパーティションだけを `dd` で切り出してから `strings` をかけ直すと、1個に絞れました。空振りではないのですが、「全体に strings」が効かないという意味では同じ系統です。

- [DISKO 2 のwriteup（note）](https://note.com/rudy_candy/n/na412247ae7b4)

## 3. メタデータ

画像を開いても何も見えず、`strings | grep academy` も0件、という問題では、画像そのものより先に付属情報を見ます。CanYouSee では `exiftool` でメタデータを出すと、本来URLが入るはずの Attribution URL の欄に、URLではない英数字の塊が入っていました。末尾が `==` で終わっていてBase64だと分かります。Base64 なので平文の `academy{` では引っかからず、`strings` の出力の中には混ざっているのに `grep` では見落とす、という作りでした。

ここで覚えておくと速いのは、Base64 にした `academy{` の頭が `YWNhZGVteX` になることです。これで `grep` すると、エンコードされたまま見つけられます。

- [CanYouSee のwriteup（note）](https://note.com/rudy_candy/n/n725e1752a7bd)

## 4. 「画像」だがテキストな形式、別形式が後ろにくっついた形式

拡張子やアイコンが画像でも、中身がテキストのことがあります。Enhance! は SVG で、実体は XML のテキストでした。フラグは `<text>` の中に1文字ずつ入っていて、しかも白い色・ほぼ0の大きさで見えなくしてあります。`grep academy` が0件だったのは、1文字ずつ空白で区切られ、タグや改行をまたいでいたからです。行単位の `grep` や `sed` はこういう相手に弱く、私はファイル全体を1つの文字列として読み直して取り出しました。

Secret of the Polyglot は、1つのファイルが PNG でもあり PDF でもあるという作りでした。`file` は先頭のマジックナンバーだけを見て「PNG」と言いますが、PDF リーダーはファイルの途中にある `%PDF` を探して開きます。フラグの前半は画像に描かれた文字、後半は PDF のテキストに分かれていて、どちらも `strings` には出ませんでした。拡張子が `.pdf` でも、`file` と `xxd` で先頭を確かめて、別の開き方を試すのが近道です。

- [Enhance! のwriteup（note）](https://note.com/rudy_candy/n/n9c41719c3949)
- [Secret of the Polyglot のwriteup（note）](https://note.com/rudy_candy/n/n3ab55cb0e17c)

## 5. ヘッダーが壊されていて中身が隠れている

`file` が「data」としか言わないファイルは、ヘッダーが壊されている疑いがあります。tunn3l v1s10n は先頭が `BM` で BMP なのに、画素データの開始位置やサイズ、画像の高さがわざと書き換えられていました。`xxd` で先頭を見て、BMP のヘッダーの並びを1項目ずつ読み、データの量から本当の高さを逆算すると、隠れていた上半分にフラグが現れます。`strings` でフラグが出ないのは、文字が画像に描かれているからです。

- [tunn3l v1s10n のwriteup（note）](https://note.com/rudy_candy/n/n214caa931e4a)

## 診断の仕事とのつながり

私は普段 Webアプリの脆弱性診断をしています。CanYouSee や Polyglot で出てくる「拡張子やMIMEだけで中身を判定すると、別物が素通りする」という話は、ファイルアップロード機能を見るときの観点そのものです。画像として受け付けたファイルが、別のソフトでは別の形式として動く、というのは実際に気にする点です。メタデータが残ったまま公開されるのも、情報が漏れるよくある形だと思っています。
