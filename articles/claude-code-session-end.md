Claude Codeを使っていると、作業の途中でセッションを切り上げる場面がよくある。そのまま閉じてしまって、次に開いたとき「あれ、どこまでやったんだっけ」と思い出すのに時間を溶かす。これを何度かやって、終わるときのひと手間で次の立ち上がりが全然違うと気づいた。私が毎回やっていることを書いておく。

先に全体の方針を一つ。Claude Codeを最大限に活かすなら、ここで挙げることはどれも**できるだけ自分で直接いじらず、Claudeに書かせる**のがいい。そのほうが速いだけでなく、Claudeが書いたものはClaude自身が次に読むときに素直に理解できる（人間が手を入れて表現や構成がちぐはぐになる、ということが起きにくい）。人間はできあがったファイルにざっと目を通す、くらいの距離感でちょうどいいと感じている。以下もその前提で読んでほしい。

## 区切りをつけて、変更を確認する

まずこれだ。中途半端でもいいので、その時点で一区切りつける。

大事なのは、終わる前に「何が変わったか」を自分の目で確認しておくこと。Claude Codeはこちらの指示の周辺も気を利かせて触ることがあるので、変更されたファイルと差分にざっと目を通して、意図しない変更が混じっていないかだけは確かめる。ここを飛ばすと、後から「いつの間にかこのファイルが変わっている」となって原因を追う羽目になる。

gitでバージョン管理しているなら、ここでコミットして区切るのが手軽だ（`git status` と `git diff` で確認してからコミット）。コミットメッセージは凝らなくていい。「どこまで進んだか」が一行で分かれば、次に開いたときの自分への引き継ぎになる。gitを使っていないなら、変更点をさっと見直してメモしておくだけでもいい。要はバージョン管理の作法そのものより、「区切って、何が変わったか把握してから閉じる」ことが効く。

## CLAUDE.md を育てる

そのセッションで分かったプロジェクト固有のこと、次回も前提になることは、CLAUDE.mdに残しておく。CLAUDE.mdは開くたびに自動で読み込まれるので、ここにあれば毎回説明し直さずに済む。

ただ、これは自分で書き足すより、Claudeと対話しながら育てるほうが楽だ。「いまの『このコマンドでテストを動かす』をCLAUDE.mdに追記しておいて」と頼めば、その場の文脈をふまえて書いてくれる。会話の中で「これ毎回言ってるな」と思ったことを、その都度Claudeに移させていく感覚でいい。「このディレクトリは触らない」「この書き方に揃える」みたいな、繰り返し効いてくるルールほど残す価値がある。

逆に言うと、同じ説明を二度している自分に気づいたら、それはCLAUDE.mdに移すサインだ。

## コードに残らない「判断と理由」をメモに残す

コードを見れば「何をしたか」は分かる。でも「なぜそうしたか」「他の案をなぜ捨てたか」は、コードには残らない。

ここがいちばん抜けやすい。次に開いたとき、過去の自分の判断の理由が分からなくて、また同じ検討を一からやってしまう。だから、迷って決めたことや、試して駄目だった方針は、短くても残しておく。

都合がいいことに、その「理由」はたいていClaudeとの会話の中に残っている。自分で書き起こさなくても、「ここまでの判断と理由を `decisions.md` にまとめておいて」と指示すれば、そのセッションのやり取りを拾ってMarkdownに整理してくれる。自分で書くより速いし、次に開いたときはそのファイルを読ませれば文脈をすぐ取り戻せる。プロジェクト全体の方針なら CLAUDE.md に、個別の判断ログなら別ファイル（例：`docs/decisions.md`）に、と粒度で使い分けるといい。

## やり残しを書き出して、次の自分に渡す

終わるときに、残っているタスクを箇条書きで書き出しておく。これも自分でまとめなくていい。「ここまでの作業で残っているタスクを `TODO.md` に書き出しておいて」と頼めば、そのセッションの流れから未完了の項目を拾ってくれる。会話を最初から最後まで追っているのはClaudeのほうなので、自分でやるより抜けが少ないことも多い。

「次はこの関数のテストから」「あの分岐がまだ未対応」くらいの粒度でいい。これがあるかないかで、次のセッションの最初の5分が変わる。次に開いたらそのファイルを読ませれば、すぐ手を動かせる。

## コンテキストを整理してから閉じる

長く続いたセッションは、会話が膨らんで文脈が散らかっている。区切りがついたら、`/compact` で要約して整理するか、いっそ `/clear` で一度区切る。

中途半端な文脈を引きずったまま次のお願いをすると、的外れな方向に進みやすい。一区切りついたタイミングで整理しておくと、次のやり取りがすっきりする。

## 長いセッションで出る「1Mコンテキスト」のエラー

文脈の話の続きで、長く引っぱったセッションでこんなエラーに出くわすことがある。私もここでつまずいた。

> api error: usage credits required for 1m context · run /usage-credits to turn them on, or /model to switch to standard context

これは100万トークンの拡張コンテキスト（1M context）に踏み込もうとしたときに出る。最近のモデルは標準の枠よりずっと大きなコンテキストを扱えるが、その1M枠は通常の枠とは別扱いで、Claude Codeでは利用にクレジット（usage credits）が必要になっている。

メッセージが言っているのは二択だ。`/usage-credits` で1M用のクレジットを有効にするか、`/model` で標準コンテキストのモデルに切り替えるか。要するに「会話が膨らみすぎて標準の枠を超えそうになっている」サインでもある。

対処は次のどれかになる。

- 本当に大きな文脈が必要なら、`/usage-credits` でクレジットを有効にする
- そこまで要らないなら、`/model` で標準コンテキストに戻す
- そもそもの予防として、さっきの `/compact` や `/clear` でコンテキストを小さく保つ

長く一つのセッションを引っぱるほど、この境界に当たりやすい。区切りのいいところで文脈を整理して閉じる習慣は、ここでも効いてくる。

### エラーが消えないときは、既知のバグを疑う

厄介なのはここからで、私が実際に引っかかったのもこれだった。**大量のファイルを扱っていて一度このエラーが出ると、セッションが時間でリセットされても、`/clear` しても、新しいセッションを開いても、ずっとエラーが続く**ことがある。文脈を減らせば直るはずなのに直らない。

調べてみると、これは自分の使いすぎではなく **Claude Code 側の既知のリグレッションバグ**だった（この記事を書いている2026年6月時点では未解決）。標準（200K）コンテキストのモデルを選んでいるはずなのに、Opus系・Sonnet系のリクエストが自動的に1Mコンテキストのティアにルーティングされてしまい、クレジット未設定だと弾かれる、という挙動が複数報告されている。新規セッションや `/clear` の直後でも出るのはこのためだ。

さらに厄介なのが、エラーメッセージの勧める対処が効かないケースがあること。`claude.ai/settings/usage` でクレジットを有効化（上限$0でも可）しても同一セッションでは直らない、`--model` でSonnetに切り替えても同じエラーが出る、という報告がある。

今のところ確実な特効薬はないが、試す価値があるのはこのあたりだ。

- **Claude Code を最新版に更新する**。リグレッションなので修正は基本アップデートで入る。まずこれを試す
- `/model`、または起動時の `--model` で標準コンテキストのモデルを明示する
- 環境変数 `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` で1Mコンテキスト自体を無効化する（拡張コンテキストの恩恵は捨てることになる）
- `claude.ai/settings/usage` でクレジットを有効化する（効く場合もある）

要は、**何をやっても1Mエラーが消えないなら、それは自分の文脈管理のせいではなくバグの可能性が高い**。深追いして時間を溶かす前に、バージョンを上げて、関連Issueの状況を見るのが早い。

参考に挙げておく。

- [Claude Code defaults to 1M context on fresh session (Pro) #62063](https://github.com/anthropics/claude-code/issues/62063)
- [false '1M context credits required' on standard-context session after /clear #64764](https://github.com/anthropics/claude-code/issues/64764)

## 散らかりの後始末

最後に、デバッグ用に出力した行や、一時的に作ったファイルが残っていないかを掃除する。これもClaudeに任せられる。「デバッグ用に足したログや一時ファイルを片付けて」と頼めば、どれが本番に要らないものかを作業の文脈から判断して消してくれる。自分でひとつずつ見分けるより、経緯を覚えているClaudeのほうが的確なことが多い。

「あとで消そう」と思った一時コードは、自分の手だとたいてい消し忘れる。終わるときにまとめて片付けさせておくと、次に開いたときにノイズがない状態から始められる。

## おわりに

書き出してみると、やることは変更の確認・CLAUDE.md・判断のメモ・やり残し・コンテキスト整理・後始末くらい。どれも数分で終わるし、しかもその多くは自分で手を動かさなくていい。「まとめておいて」「片付けておいて」とClaudeに頼んで、自分は最後にファイルへ目を通すだけでいい。

セッションをぶつ切りで終わらせず、次の自分が困らない状態にして閉じる。そして、その作業の大半までAIに任せられる。それがClaude Codeで働くときの、いちばん楽なところだと思う。
