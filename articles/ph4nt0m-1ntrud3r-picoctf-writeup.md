ネットワークフォレンジックで一番ハマりやすい罠は「順番」です。Ph4nt0m 1ntrud3rはその罠をそのまま問題にしたチャレンジでした。

## やってしまった失敗

pcapを開いてBase64文字列を発見した瞬間、「これをデコードして繋げれば終わり」と思った。

Wiresharkの「Follow TCP Stream」でペイロードを結合してデコードしたら……意味不明な文字列が出た。`nt_th4t66d0bfb{1t_w4s...` みたいな感じ。

「暗号化されてる？」「ROT13?」とか試し始めて20分無駄にした。

## 問題の本質

このpcapには22パケット、うち7つにBase64フラグメントが含まれていた。全部ほぼ同時刻（5ミリ秒以内）に送られているが、**到着順（キャプチャ順）とタイムスタンプ順が違う**。

ペイロードをマイクロ秒のタイムスタンプで並び替えると：

| タイムスタンプ(usec) | デコード結果 |
|---|---|
| 578407 | `picoCTF` |
| 578629 | `{1t_w4s` |
| 578863 | `nt_th4t` |
| 579198 | `_34sy_t` |
| 579422 | `bh_4r_9` |
| 579649 | `66d0bfb` |
| 579868 | `}` |

タイムスタンプ順に繋げると `picoCTF{1t_w4snt_th4t_34sy_tbh_4r_966d0bfb}` になる。

## 覚えておくべき教訓

**Base64を結合しても意味不明なら、まずソート順を疑う。** 暗号化より先にタイムスタンプ・シーケンス番号・何らかのインデックスで並び替えを試みること。

また `tcp.len > 0` というWiresharkフィルタは反射的に使うようになった。ペイロードのないTCPパケットを除外して関係ある7パケットだけ見れれば、構造が一目でわかる。

## セキュリティ的な意味

これは「コバートチャネル」と呼ばれる実在の攻撃手法をモデルにしている。出力データをパケット順序に隠して送信することで、内容を見ただけでは気づかれにくくする。IDS（侵入検知システム）がパケットをバッファリングしてソートしないと検出できない。
