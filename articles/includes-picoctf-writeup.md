Web Exploitationの入門として位置づけられる問題です。「ソースを見る」という基本動作から始まりますが、最初に間違ったツールを選ぶとすぐ迷子になります。

## やらかした失敗

ページに「Say Hello」ボタンがあって、クリックすると「This code is in a separate file!」というポップアップが出た。

「なるほど外部JSか」と思い、反射的にBurpSuiteを起動して通信を傍受しようとした。

結果：HTTPトラフィックには何も有益な情報がなかった。フラグはすでに静的ファイルとしてブラウザに届いていたので、BurpSuiteで見えるものはページソースを見るのと同じだった。10分無駄にした。

## この問題の構造

ページソースを読むと、CSSとJSの2ファイルが読み込まれている。

- `style.css`：CSSブロックコメント `/* */` の中にフラグの前半
- `script.js`：JSコメント `//` の末尾にフラグの後半

フラグが分割されていて、JSファイルのコメントを見ると `f7w_2of2_6edef411}` という文字列が出てくる。

「2of2」という表記がそのまま「これは2パーツのうちの2番目」を意味している。自己申告型のヒントになっている。これに気づかずにタブを閉じかけた。

## BurpSuiteを使うべきタイミングの判断軸

この問題で学べた判断基準：

- データがHTTPリクエストとして**送受信されている**場合 → BurpSuite
- データがページ読み込み時に**すでにブラウザへ届いている**場合 → ページソース・DevTools

ボタンを押してポップアップが出るだけなら、その動作は静的JSで実装されている可能性が高い。動的なサーバーレスポンスが含まれるかどうかを先に判断してからツールを選ぶべきだった。

## セキュリティ的な意味

実際の脆弱性診断でも「ソースコード閲覧」は最初の調査ステップです。

- HTMLコメントに残ったデバッグ情報
- JavaScriptにハードコードされたAPIキーや認証情報
- CSSに含まれる内部パスやサーバー情報

バグバウンティでは「JSバンドルにAPIキーが混入していた」という報告が定期的に上がっています。Includesはその感覚を掴むための問題です。
