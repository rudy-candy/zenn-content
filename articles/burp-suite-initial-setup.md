Burp Suiteをインストールしたものの、診断を始める前にどこを設定すればいいのか分からない。私がセキュリティ会社の研修で最初に触ったときが、まさにそうだった。この記事では、**Burp Suiteの初期設定として最低限やっておくこと**を、手順だけに絞ってまとめる。ここでつまずくと診断どころではないので、新人に説明するつもりで順番に書いていく。

対象はBurp Suite Community Edition（無料版）。Professionalでも初期設定の流れは同じだ。

## Burp Suiteとは何をするツールか

ひとことで言うと、**ブラウザとサーバーの間に割り込んで、通信を見たり書き換えたりするためのプロキシツール**だ。

診断では「リクエストを止めて、パラメータを書き換えて、レスポンスがどう変わるか見る」という作業を延々とやる。その土台になるのがBurpで、最初にやるべきは「ブラウザの通信をBurpに通す」設定になる。

## 1. Burp Suiteのインストールと起動

[公式サイト](https://portswigger.net/burp)からCommunity Editionをダウンロードしてインストールする。Javaは同梱されているので別途用意しなくていい。

起動すると最初にプロジェクトの種類を聞かれる。Community版では「Temporary project」しか選べないので、そのまま進めて問題ない。設定も最初は「Use Burp defaults」でいい。

## 2. Proxyのリスナーを確認する

Burpはデフォルトで `127.0.0.1:8080` で待ち受けている。ここを通った通信が記録・操作の対象になる。

`Proxy` タブ → `Proxy settings`（バージョンによっては `Options`）を開き、Proxy listenersに `127.0.0.1:8080` が `Running` になっているか確認する。たいていは何もしなくても動いているが、別のソフトが8080を使っていると起動に失敗するので、その時はここでポートを変える。

## 3. ブラウザの準備 — 内蔵ブラウザが一番速い

昔は外部ブラウザにプロキシ設定をして、証明書を入れて……と手間がかかった。今は**Burpの内蔵ブラウザを使うのが圧倒的に楽**だ。

`Proxy` → `Intercept` タブの `Open Browser` を押すだけで、プロキシ設定も証明書も済んだ状態のChromiumが立ち上がる。検証作業はまずこれで始めるのをおすすめする。

外部のブラウザ（普段使いのChromeなど）を使いたい場合だけ、次の証明書の作業が必要になる。

## 4. CA証明書のインストール（HTTPSを見るため）

外部ブラウザを使う場合、HTTPS通信はそのままだと暗号化されていて中身が読めない。Burpの証明書をブラウザに信頼させることで、復号して中身を見られるようになる。

1. ブラウザのプロキシを `127.0.0.1:8080` に向ける（FoxyProxyなどの拡張を使うと切り替えが楽）
2. その状態で `http://burp` にアクセスする
3. 右上の `CA Certificate` から証明書をダウンロードする
4. ダウンロードした証明書を、ブラウザ（またはOS）の信頼されたルート証明書としてインポートする

ここを飛ばすと、HTTPSサイトで証明書エラーが出て通信が見えない。新人がよく詰まるポイントなので、内蔵ブラウザで済むならそちらを使ったほうがいい。

## 5. Interceptのオン/オフを理解する

`Proxy` → `Intercept` の `Intercept is on/off` は、**リクエストを途中で止めるかどうか**のスイッチだ。

onにすると一つひとつのリクエストで止まるので、最初は「画面が進まない」と戸惑う。普段はoffにしておき、止めて書き換えたいときだけonにする。記録自体は `HTTP history` に残り続けるので、後から見返せる。

## 6. Scope設定 — これが実務では一番大事

診断で絶対にやるべきなのがScope（対象範囲）の設定だ。

`Target` → `Scope settings` で診断対象のドメインを登録する。これをやらないと、対象サイトが読み込む広告や外部サービスへの通信まで全部記録されて、履歴が一瞬で埋まる。

さらに「スコープ外の通信を記録しない」設定にしておくと、履歴が対象サイトの通信だけになって一気に見やすくなる。**スコープ外を触らない**のは技術的な見やすさの問題だけでなく、許可されていない範囲に手を出さないという、診断のルール上も重要なことだ。

## まとめ

最低限ここまでやれば、診断を始められる。

- インストールして起動する
- Proxyが `127.0.0.1:8080` で動いているか確認する
- まずは内蔵ブラウザで通信を通す（外部ブラウザなら証明書を入れる）
- Interceptは普段off、必要なときだけon
- 対象ドメインをScopeに登録する

ツールの設定が終わってからが本番だ。実際の診断がどう進み、どんな脆弱性が見つかるのかは、自分の実務経験をもとに一冊にまとめました。あわせてどうぞ。
