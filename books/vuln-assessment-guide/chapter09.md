## 9-1 Burp Suiteの全体像

Burp Suiteはタブで機能が分かれている。実務で特に使うのは以下の5つだ。

| タブ | 用途 |
|---|---|
| **Proxy** | ブラウザの通信を中継・記録する |
| **Repeater** | リクエストを手動で書き換えて再送する |
| **Intruder** | パラメータに自動でペイロードを送り込む |
| **Decoder** | URLエンコード・Base64などの変換を行う |
| **Comparer** | 2つのレスポンスを比較する |

この章ではそれぞれの実践的な使い方を説明する。

---

## 9-2 Proxy：通信の記録と管理

### HTTP historyの活用

Proxy → HTTP historyにはブラウザで行ったすべての通信が記録される。クローリング中にここを確認しながら、診断対象のリクエストを把握していく。

**効率化のコツ**
- 「Filter」でステータスコードや拡張子を絞り込む（画像・CSSなど不要なリクエストを除外）
- 診断対象のドメインだけに絞るにはTarget → Scopeで対象を設定する
- 気になるリクエストは右クリック → 「Add comment」でメモを残せる
- 重要なリクエストは色でハイライト（右クリック → Highlight）しておくと後で見つけやすい

### スコープの設定

診断対象外のドメインへのリクエストまで記録されると、HTTP historyが膨大になる。Target → Scopeでホスト名を追加しておくと、関係ないリクエストをフィルタできる。

```
Target → Scope → Include in scope に診断対象ドメインを追加
```

スコープ外のリクエストをHTTP historyに記録しない設定もあるため、クローリング前に設定しておくと作業がしやすい。

## 9-3 Repeater：手動検証の中心ツール

RepeaterはBurp Suiteの中で最も使用頻度が高い機能だ。リクエストを手動で書き換えて何度でも送り直せる。

### 基本的な使い方

1. HTTP historyで対象リクエストを右クリック → 「Send to Repeater」（ショートカット：`Ctrl + R`）
2. Repeaterタブに移動する
3. リクエストの該当パラメータを書き換える
4. 「Send」ボタンで送信し、右側のResponseを確認する

### 実務での使い方

**SQLインジェクションの検証**
パラメータの値を `'` や `AND 1=1` に書き換えて送信し、エラーや挙動の変化を確認する。Repeaterなら同じリクエストを繰り返し試せる。

**認可チェック**
ユーザーAのセッションCookieでリクエストを送った後、CookieをユーザーBのものに差し替えて再送する。レスポンスが変わらなければ認可が機能していない。

**ヘッダの操作**
レスポンスヘッダを確認したい場合、RequestにヘッダをひとつずつRemoveしながら送り直すことで、どのヘッダが影響しているかを特定できる。

## 9-4 Intruder：自動化したパラメータ検証

Intruderは指定したパラメータに対してペイロード（検査文字列のリスト）を自動で送り込む機能だ。手動では時間がかかる大量の検証を効率化できる。

### 基本的な使い方

1. 対象リクエストをIntruderに送る（`Ctrl + I`）
2. 「Positions」タブで変更したいパラメータを `§` で囲む
3. 「Payloads」タブでペイロードリスト（検査文字列の一覧）を設定する
4. 「Start attack」で実行する

### Community Editionの制限

Community EditionではIntruderのリクエスト速度が意図的に制限されている。大量のリクエストを素早く送りたい場合はProfessional Editionが必要だ。

実務（Professional Edition）では、パスワードリストを使ったブルートフォースの検証や、XSSのペイロードリストを使った一括検証に使う。

---

## 9-5 Decoder：エンコードされた値の解読

WebアプリのパラメータはURLエンコードやBase64でエンコードされていることが多い。Decoderを使うと素早く変換できる。

### 主な使い方

- URLエンコードされたパラメータを読みやすくデコードする
- Base64エンコードされたCookieの内容を確認する
- 検査文字列をURLエンコードしてパラメータに埋め込む

HTTP historyでパラメータの値を選択 → 右クリック → 「Send to Decoder」で直接Decoderに送れる。

---

## 9-6 Comparer：レスポンスの差異を見つける

Comparerは2つのリクエスト・レスポンスを並べて差分を確認するツールだ。

### 実務での活用

**ブラインドSQLインジェクションの確認**
`AND 1=1`（真）のレスポンスと `AND 1=2`（偽）のレスポンスをComparerで比較すると、どこが変化しているかが一目でわかる。レスポンスが長い場合に特に有効だ。

**認可確認の比較**
権限のあるユーザーのレスポンスと権限のないユーザーのレスポンスを比較することで、アクセス制御の有無を素早く判断できる。

### 使い方

HTTP historyまたはRepeaterでレスポンスを右クリック → 「Send to Comparer（response）」を選び、比較したい2つのレスポンスを送ってComparerタブで確認する。

## 9-7 実務で役立つショートカットと設定

### よく使うショートカット

| 操作 | ショートカット |
|---|---|
| RepeaterへSend | `Ctrl + R` |
| IntruderへSend | `Ctrl + I` |
| リクエスト送信（Repeater） | `Ctrl + Enter` |

### CA証明書のインストール確認

HTTPSサイトの通信がBurp Suiteで確認できない場合、CA証明書が正しくインストールされていない可能性がある（第2章参照）。Proxy → Proxy settingsでリスナーが `127.0.0.1:8080` で動作しているかも確認する。

### リクエストのエクスポート

RepeaterやHTTP historyのリクエストはコピーしてテキストファイルに保存できる。報告書のエビデンスとして貼り付けるときに使う。右クリック → 「Copy as curl command」でcurl形式に変換すると再現性が高く便利だ。

### セッションCookieの管理

複数の権限を切り替えて認可テストを行うとき、各アカウントのCookieをメモしておくと作業しやすい。RepeaterでCookieヘッダを直接書き換えることで、ブラウザでログインし直さずに別アカウントのリクエストを送れる。
